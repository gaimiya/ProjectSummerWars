# 分担と進め方

## だれがどこを触るか
| 人 | 主なフォルダ（src/main/java/app/kintai の下） | ひとことで |
|---|---|---|
| 指輪 | templates・static（画面）、settings、全体のまとめ | 画面と設定、切り替えの段取り |
| 横田 | attendance、**aggregate** | 勤怠を読んで、計算する |
| 山川 | monthly、expense、config（ログイン）、db/migration | 集計を保存して社労士へ渡す、ログイン、DB |
| 宮谷 | employee、google | 社員管理と Google 連携 |

各フォルダの README.md に、中身・やること・守ることを書いてある。まず自分のフォルダの README を読む。

## まず最初にやること（1週目）
- **指輪**：GAS からの切り替え手順（docs/GAS停止手順.md）を進める。本番サーバーの置き場所を決める
- **横田**：社労士に集計ルールを確認する質問を作る（aggregate/README.md の「やること」）
- **山川**：社労士が読める CSV の形を確認する。交通費・経費フォームの回答シートに「承認」列を足す
- **宮谷**：サービスアカウントを作り、本物の Google で社員登録〜共有を確かめる

## Git の使い方（ぶつからないように）
1. 作業を始める前に `git pull`
2. 作業ごとにブランチを作る：`git switch -c 名前/作業内容`（例：`yokota/overtime-rule`）
3. こまめにコミット：`git commit -m "残業を週40時間で数える"`
4. `git push` して、GitHub で Pull Request を作る。だれか1人に見てもらってから main に入れる
5. Actions（自動テスト）が緑になってから入れる

- 他の人のフォルダを直すときは、その人に一言かける（Pull Request に名前を書く）
- 鍵ファイル・パスワードは絶対にコミットしない
- 迷ったら GitHub の Issue に書く（#1 に全体の課題がある）
